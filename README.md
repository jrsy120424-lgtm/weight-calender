# 体重日历（Android）

一款离线优先的原生安卓体重记录应用。开发方向：Kotlin + Jetpack Compose；云端构建：Gradle + GitHub Actions。第一版不需要账号、服务器、广告或付费 API。

## 功能

- 每日记录体重，可为任意日期补录或修改。
- 可选单位：千克（kg）、斤、两；底层统一以千克保存。
- 首页显示与上一日（严格指日历前一天）及第一条记录的差值。
- 日历按月查看记录；历史页按日期查看全部记录。
- 基金计算：独立输入“两数”，按每两 ¥10 计算金额，显示换算为斤、千克的过程；不自动把体重变化和金额绑定。
- 体重差值只用于记录观察，不建议为了金额刻意追求体重变化。
- 支持把记录导出成 JSON 文件，也可从 JSON 备份恢复。
- 清爽浅蓝 UI；应用图标为体重秤 + 日历组合。

## 单位关系

- 1 千克 = 2 斤 = 20 两
- 1 斤 = 0.5 千克 = 10 两
- 1 两 = 0.05 千克 = 0.1 斤
- 基金计算金额 = 输入的两数 × ¥10；例如 2 两 × ¥10/两 = ¥20

## 数据存储说明

数据保存在应用私有的本地 SharedPreferences 中，不会上传到网络。正常情况下，关闭应用或重启手机后记录仍会保留。但“永久”不代表绝对不会丢失：卸载应用、清除应用数据或设备损坏都可能导致记录丢失。建议定期在“历史”页导出 JSON 备份，并保存到安全位置。恢复备份会用备份文件中的记录替换当前记录，请先导出当前数据以免覆盖。

## 项目结构

- `app/src/main/java/com/weightcalendar/app/MainActivity.kt`：界面、记录、差值、基金金额计算与备份恢复逻辑。
- `app/src/main/AndroidManifest.xml`：应用入口与标签。
- `app/src/main/res/`：图标和主题资源。
- `.github/workflows/android-build.yml`：推送代码时自动构建 APK。

## 在手机上零成本构建 APK

1. 在手机浏览器打开 https://github.com/ ，登录后创建仓库（建议先设为 Private，避免代码公开）。
2. 推荐用更适合手机的 ZIP 构建法：先把 `体重日历_Android源码.zip` 上传到仓库根目录（上传 ZIP 本身，不要解压上传）。然后在 GitHub 里选择 **Add file → Create new file**，文件名填写 `.github/workflows/build.yml`，把单独提供的 `体重日历_手机端快速构建工作流.yml` 文件内容复制粘贴进去，提交保存。
   - 也可以把 ZIP 解压后上传所有项目文件，但必须保留 `.github/workflows/android-build.yml` 路径。
3. 提交到 `main` 或 `master` 分支后，打开仓库的 **Actions** 页面，进入 **Build Weight Calendar APK from ZIP**（ZIP 上传法）或 **Build Weight Calendar APK**（解压上传法）工作流。
4. 等待任务完成，打开最近一次成功的运行记录，在 **Artifacts** 下载 `体重日历-APK`，解压后得到 `体重日历-debug.apk`。
5. 在安卓手机上打开 APK 安装。系统可能会询问是否允许当前来源安装应用；只允许来自你信任的文件管理器/浏览器的安装。

也可在 **Actions** 里点 **Run workflow** 手动触发。源码构建无需付费 API 或服务器。GitHub Actions 的免费额度受仓库可见性和账号套餐规则影响；标准运行器对公开仓库的使用通常免费，私有仓库则按账号免费额度执行。请在 GitHub 计费页面确认自己的额度，避免超额付费。

## 调试签名说明

项目内附固定的**调试用**签名密钥，以便同一份构建配置生成的后续测试 APK 可以覆盖安装、保留本机记录。请把代码仓库设为 Private；该密钥仅用于个人测试，绝不可用于正式商店发布。正式发布需要自行生成和安全保存专用的 release 签名密钥。

## 已知限制 / 后续可扩展

- 第一版使用本地存储；换手机前需要导出并恢复备份。
- 奖励按第一条记录与最近一条记录之间的总变化计算，不区分期间的体重反弹。
- “较上一日”只在前一个自然日存在记录时显示；如果中间漏记，不会把更早的记录冒充为“上一日”。
- 若需发布到应用商店，应另行配置正式签名、隐私说明和商店资料。
